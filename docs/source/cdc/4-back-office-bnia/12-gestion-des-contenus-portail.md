# 4.12 Gestion des contenus portail
Le module de gestion des contenus portail doit permettre au BNIA d’alimenter, organiser et mettre à jour les contenus documentaires diffusés aux opérateurs dans leur espace dédié. Il couvre les actualités, les informations pratiques, les ressources et la photothèque. 

## 4.12.1 Catégories d’actualités
Le module doit permettre de gérer les catégories utilisées pour classer les actualités visibles dans le portail opérateur. 

Le BNIA doit pouvoir : 

- consulter la liste des catégories; 

- créer / modifier / supprimer une catégorie; 

- définir l’ordre d’apparition des catégories. 

Chaque catégorie doit comporter un libellé et une photo associée pour l’illustrer. 

## 4.12.2 Articles d’actualité
Le module doit permettre de gérer les articles publiés dans le portail opérateur. 

Chaque article doit permettre de renseigner : 

- la date de publication; 

- la catégorie associée; 

- une photo; 

- le titre; 

- un contenu mis en forme. 

L’éditeur de contenu doit permettre au BNIA d’appliquer les mises en forme utiles, notamment le gras, l’italique, le soulignement, les listes à puces, les couleurs, la taille de texte et les liens vers des ressources internes ou des `URL` externes. 

## 4.12.3 Interlocuteurs BNIA
Le module doit permettre de gérer la liste des interlocuteurs affichés dans les informations pratiques du portail. 

Le BNIA doit pouvoir : 

- consulter les interlocuteurs existants; 

- ajouter un interlocuteur; 

- modifier un interlocuteur; 

- supprimer un interlocuteur; 

- définir l’ordre d’apparition.

<!-- p.55 -->
Chaque interlocuteur doit comporter : 

- le rôle; 

- le nom; 

- le prénom; 

- l’adresse électronique; 

- le numéro de téléphone. 

## 4.12.4 Horaires du BNIA
Le module doit permettre de paramétrer les horaires et informations pratiques du BNIA sous forme de contenu texte mis en forme. 

Cette zone doit permettre d’afficher un contenu libre, lisible dans le portail et administrable sans intervention technique. 

## 4.12.5 Catégories et sous-catégories de ressources
Le module doit permettre de structurer la bibliothèque documentaire du portail par catégories et sous-catégories. 

Le BNIA doit pouvoir : 

- créer, modifier et supprimer une catégorie; 

- définir l’ordre d’apparition des catégories; 

- rattacher une catégorie à une catégorie parente; 

- limiter l’arborescence à deux niveaux : parent et enfant. 

## 4.12.6 Documents ressources
Le module doit permettre de gérer les documents mis à disposition dans le portail. 

Le BNIA doit pouvoir : 

- consulter le listing des documents; 

- ajouter un document; 

- modifier un document; 

- supprimer un document; 

- rattacher un document à une catégorie ou sous-catégorie. 

Chaque document doit comporter : 

- un titre; 

- une catégorie ou sous-catégorie de rattachement; 

- un fichier déposé.

<!-- p.56 -->
Les formats de fichiers pris en charge doivent couvrir les documents et médias utiles au portail, notamment `PDF` , `ZIP` , `JPEG` , `PNG` , `DOC` , `DOCX` , `XLS` et `XLSX` . 

## 4.12.7 Catégories de photothèque
Le module doit permettre de gérer les catégories utilisées pour la photothèque du portail. Le BNIA doit pouvoir : 

- consulter les catégories existantes; 

- ajouter une catégorie; 

- modifier une catégorie; 

- supprimer une catégorie; 

- définir l’ordre d’apparition. 

Chaque catégorie doit comporter un libellé. 

## 4.12.8 Photos de photothèque
Le module doit permettre de gérer les photos diffusées dans la photothèque du portail. 

Le BNIA doit pouvoir : 

- consulter les photos existantes; 

- ajouter une photo; 

- modifier son rattachement; 

- supprimer une photo; 

- rattacher chaque photo à une catégorie. 

Les formats d’image attendus sont `JPEG` et `PNG` . 

Le détail des champs est décrit dans l’annexe Référentiel des données et objets de gestion.

# 4.13 Boutique et gestion des commandes
Le module boutique doit permettre au BNIA d’administrer une offre simple de produits destinés aux opérateurs, de suivre les commandes passées depuis le portail et d’en assurer le traitement jusqu’à la facturation. 

## 4.13.1 Catégories de produits
Le BNIA doit pouvoir gérer les catégories utilisées pour classer les produits visibles dans la boutique. 

Le module doit permettre : 

- de consulter la liste des catégories; 

- d’ajouter une catégorie; 

- de modifier une catégorie; 

- de supprimer une catégorie. 

Chaque catégorie doit comporter un intitulé. 

## 4.13.2 Produits boutique
Le module doit permettre de gérer les produits proposés à la commande. 

Le BNIA doit pouvoir : 

- consulter le listing des produits; 

- ajouter un produit; 

- modifier un produit; 

- supprimer un produit; 

- rattacher un produit à une catégorie. 

Chaque produit doit comporter : 

- une photo; 

- un intitulé; 

- un prix unitaire `HT` .
